# 1단계 진단기 설계

> 코드: `scanner/`. 정답셋 생성기: `testkit/`. 시험: `tests/`.
> 이 문서는 진단기가 **무엇을 어떻게 판정하는지**의 정의서다. 정의를 바꾸면 `scanner/folders.py`와
> 정답 계산기 `testkit/oracle.py`를 함께 고치고, 정답셋 시험이 통과하는지 확인한다.

## 1. 흐름

```
목록 만들기 → 해시 계산 → 완전 중복 묶기 → 중첩 백업 찾기 → 보고서
inventory.py  hashing.py   duplicates.py     folders.py        report.py
```

| 단계 | 하는 일 | 읽는 것 | 쓰는 곳 |
| --- | --- | --- | --- |
| 목록 | 폴더를 훑어 크기·날짜·속성·표지를 적음 | 폴더 목록, 파일 속성 | 출력 폴더의 `scan.sqlite` |
| 해시 | 크기가 같은 파일만 앞 64KB → 전체 순으로 BLAKE2b | 파일 내용(읽기 전용) | `scan.sqlite` |
| 완전중복 | 전체 해시가 같은 파일끼리 묶음 | DB | `scan.sqlite` |
| 중첩 백업 | 폴더 단위 비교 (아래 4장) | DB | `scan.sqlite` |
| 보고서 | HTML 1장, 엑셀 상세, 요약 숫자 | DB | `진단보고서.html`, `진단상세.xlsx`, `요약숫자.json` |

## 2. 읽기 전용을 지키는 장치

1. **쓰는 곳은 한 파일뿐**: `scanner/output.py`만 파일을 쓴다. 출력 폴더 안, 이름 하나짜리 파일만 쓸 수 있다.
   - 새 폴더이거나, 이 프로그램이 전에 만든 폴더(표지 `.filetidy-output`이 있는 폴더)만 출력 폴더로 받는다.
   - 출력 폴더가 검사 시작점과 같거나 그 위면 거부한다.
2. **소스 검사 시험** (`tests/test_safety_static.py`, 검사기 `tests/safety_rules.py`)
   - 삭제 금지: `scanner`·`executor`·`testkit`·맨 위 `.py` 어디에도 `remove`·`unlink`·`rmtree`·`send2trash`·`DeleteFileW` 등이 없어야 한다. `getattr(os, "remove")`나 `del`·`rd` 셸 명령 문자열도 잡는다.
   - 쓰기 금지: `scanner`(단 `output.py` 제외)에 이동·이름 변경·복사·날짜/속성 변경·쓰기 모드 열기·외부 명령·DB/엑셀 파일 직접 만들기가 없어야 한다.
   - 검사기 자체도 일부러 넣은 나쁜 코드 조각을 잡는지 시험한다.
3. **실행 시험** (`tests/test_readonly.py`): 진단 전후로 검사 대상 모든 파일의 경로·크기·수정 시각·속성·SHA-256이 같은지 비교한다. 같은 출력 폴더로 두 번 돌려 이어 하기 경로도 확인한다.
4. 출력 폴더와, 표지 파일이 든 예전 출력 폴더는 검사에서 자동으로 빠진다.
5. 알아 둘 점: 파일을 읽으면 윈도우 설정에 따라 '마지막 접근 시각'이 갱신될 수 있다. 내용·크기·만든 날짜·수정한 날짜는 바뀌지 않는다.
   문서보안(DRM) 프로그램이 다른 프로그램의 파일 열기를 기록하거나 막을 수 있다 — 막히면 오류 표에 적히고 진단은 계속된다.

## 3. 목록 만들기

- 파일마다: 볼륨 일련번호(드라이브 문자 대신 이것으로 구별), 드라이브 문자, 전체 경로, 폴더, 이름, 확장자, 크기, 만든·수정 시각, 속성(읽기 전용·숨김·시스템).
- **표지**(판정이 아니라 단서)
  - 복사본(날짜): 만든 시각이 수정 시각보다 2초 넘게 늦음. 윈도우는 복사할 때 만든 날짜를 새로 찍고 수정 날짜는 원본을 따르기 때문.
  - 복사본(이름): ` - 복사본`, ` - Copy`, `Copy of`, `(숫자)`. '붙임(1)' 같은 정상 이름도 걸릴 수 있다.
  - 임시파일: `~$`로 시작, `.tmp`.
- **건너뜀**: 제외 목록, 출력 폴더, 바로가기 폴더(정션)·심볼릭 링크(따라가지 않음 — 무한 고리 방지), 클라우드 자리표시자(내용이 PC에 없어 읽지 않음).
- **오류**: 접근 거부·경로 없음·이름 오류 등은 오류 표에 적고 계속한다. 목록을 끝까지 못 읽은 폴더는 '불완전'으로 표시한다.
- **긴 경로**: 윈도우에서는 모든 파일 시스템 호출에 `\\?\` 접두사를 붙인다. 경로는 검사 시작점만 정리하고 나머지는 이름을 그대로 이어 붙인다(`\\?\`는 끝 공백·마침표를 고치지 않으므로).
- **이름 글자 문제**: 깨진 유니코드·cp949 바이트 이름은 DB에는 `\xNN` 꼴로 적고, 원래 바이트는 `path_raw`에 따로 둔다.

### 기본 제외 목록 (드라이브 맨 위 기준)

인계서 지정: `/Windows`, `/Program Files`, `/Program Files (x86)`, `/ProgramData`, `/Users/*/AppData`, `**/$Recycle.Bin`, `**/System Volume Information`
추가(운영체제 파일): `/pagefile.sys`, `/hiberfil.sys`, `/swapfile.sys`, `/DumpStack.log.tmp`, `/Recovery`, `/Config.Msi`, `/$WinREAgent`, `/$Windows.~BT`, `/$Windows.~WS`, 그리고 `/Windows.old` 안의 시스템 폴더(사용자 문서는 검사).

## 4. 판정 정의

### 4-1. 완전 중복
전체 해시(BLAKE2b-256)와 크기가 같은 파일끼리 한 묶음. **0바이트 파일은 묶지 않고 따로 센다.**
회수 가능 용량 = Σ (묶음 파일 수 − 1) × 크기.

### 4-2. 내용 번호
- 중복 묶음에 든 내용 → 공유 번호
- 0바이트 → '빈 내용'
- 중복이 없는 내용, 해시를 못 읽은 파일, 자리표시자 → 그 파일만의 번호

### 4-3. 폴더
- **깨끗한 폴더**: 하위 전체에 파일이 하나 이상 있고, 모든 파일이 공유 번호나 빈 내용이며, 목록을 끝까지 읽은 폴더. 그만의 번호가 하나라도 있으면 다른 곳에 같은 폴더가 있을 수 없다.
- **비교 대상**: 깨끗하고 용량이 0보다 큰 폴더.

| 수준 | 정의 |
| --- | --- |
| (a) 구조·이름까지 같음 | 하위 (상대 경로, 내용 번호) 목록이 같다. 이름은 유니코드 NFC + 대소문자 무시로 비교. 빈 하위 폴더는 무시 |
| (b) 내용만 같음 | 하위 내용 번호 **집합**이 같다. 이름·배치가 다르거나, 폴더 하나로 감싼 경우 |
| (c) 포함 | A의 내용 집합이 B 안에 모두 있고 B가 더 많다. B는 그런 폴더 중 **가장 작은 것**(자손 중에 A를 품는 폴더가 없는 것). B와 내용이 같은 폴더가 B 아래에 있으면 (c)가 아니라 (b) |

- 서로 조상·자손인 폴더는 비교하지 않는다.
- (a)(b)는 내용 집합이 같은 폴더끼리 한 **묶음**으로 낸다. 같은 묶음 안에 조상·자손이 함께 들면 위쪽만 남긴다(감싼 폴더 쪽으로 접기). 묶음 수준은 보여 주는 구성원이 모두 같은 구조면 a, 섞였으면 b. 구성원마다 '구조 번호'를 붙여 같은 구조끼리 같은 번호.

### 4-4. 접기 (큰 폴더부터)
위에서 아래로 내려가며:
- 어떤 폴더가 묶음 구성원이거나 (c)의 안쪽이면 그 아래 폴더들은 **접힌다**(따로 보고하지 않음).
- 묶음에서 접히지 않은 구성원이 둘 이상이면 그들만 보고한다.
- 하나뿐이면, 접힌 구성원 중 경로가 가장 앞선 것을 **'참고'**로 함께 보여 준다. (예: `D:\옛날자료\2023업무`가 이미 겹친 `전임자백업` 안의 `2023업무`와 같을 때)
- 접힌 폴더는 (c)의 안쪽으로도 보고하지 않는다. 바깥쪽은 접혀 있어도 된다.

### 4-5. 왜 이렇게 정했나
- '깨끗한 폴더'만 비교하므로, 실제 업무 PC에서 대부분의 폴더(고유 파일이 하나라도 있는 폴더)는 계산에서 바로 빠진다.
- 내용 집합으로 비교하므로 "하나만 남겨도 잃는 내용이 없다"는 뜻과 일치한다.
- 못 읽은 파일·폴더는 고유 번호로 다루어, 확인하지 못한 것을 중복이라 말하지 않는다(보수적).

## 5. 구현 메모 (`scanner/folders.py`)

- 아래에서 위로: 파일 수·용량·깨끗함, 구조 해시(머클 방식: 자식 폴더 해시와 파일 (이름, 번호)를 정렬해 BLAKE2b), 내용 집합(깨끗한 폴더만).
- (c) 계산: 오일러 순회 번호로 "X 아래에 내용 c가 있나"를 이분 탐색으로 답한다. A의 내용 중 가장 드문 것이 있는 곳의 조상들을 후보로 잡고, 나머지 내용으로 후보를 걸러 낸다.
- 정답 계산기 `testkit/oracle.py`는 같은 정의를 모든 폴더 쌍의 집합 비교로 계산한다. 두 구현이 독립이라, 결과가 같으면 빠른 구현이 맞다고 본다.
  - 정답셋 시험(`tests/test_accuracy.py`)과 무작위 나무 교차 시험(`tests/test_random_trees.py`, 기본 12개, `FILETIDY_RANDOM_SEEDS=300`으로 300개)에서 일치를 확인했다.

## 6. 이어 하기

- 같은 출력 폴더로 다시 실행하면 같은 DB를 쓴다. 파일은 경로로 찾아 갱신한다.
- `크기:수정 시각:만든 시각`이 그대로면 전에 계산한 해시를 다시 쓴다. 바뀌었으면 버리고 다시 계산한다.
- 해시는 1초마다 저장(commit)하므로, 강제 종료돼도 그 전까지 계산한 것은 남는다.
- 읽는 동안 크기·수정 시각이 바뀐 파일은 해시를 저장하지 않고 오류('읽는중변경')로 적는다.
- 분석 결과는 실행 번호별로 쌓는다(DB 안에서도 지우지 않는다).

## 7. DB 표 (scan.sqlite)

| 표 | 내용 |
| --- | --- |
| `runs` | 실행 번호, 시각, 옵션, 단계별 통계 |
| `volumes` | 볼륨 일련번호(열쇠), 이름, 형식, 마지막 드라이브 문자, 전체·남은 공간 |
| `roots`, `dirs`, `files` | 검사 시작점, 폴더, 파일 (경로, 원래 바이트, 크기, 날짜, 속성, 표지, 해시) |

| `dup_groups`, `dup_members` | 완전 중복 묶음 |
| `folder_groups`, `folder_members`, `folder_contains` | 중첩 백업 묶음과 포함 관계 |
