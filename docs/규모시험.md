# 규모 시험 기록

합성 정답셋에 대량 파일(`--scale N`, 파일 ≈ 49 × N)을 더해 진단 시간을 잰다.

```
FILETIDY_SCALE=5000 FILETIDY_SCALE_REPORT=결과.json python -m pytest tests/test_scale.py -s
```

윈도우 결과는 GitHub Actions 「시험·빌드」 실행 요약(Summary)에 자동으로 적힌다(기본 400묶음, 약 2만 개).
수동 실행(workflow_dispatch) 때 묶음 수를 바꿀 수 있다.

- 다시 진단할 때 해시는 하나도 다시 계산하지 않았다(목록·보고서만 다시 함).

## 해석할 때 주의

- **합성 파일은 아주 작다**(평균 약 200바이트). 실제 업무 PC에서는 같은 크기 파일을 읽는 '해시' 단계가 디스크 속도에 따라 훨씬 오래 걸린다. 예: 같은 크기 파일이 100GB라면 하드디스크(초당 약 100MB)에서 전체 해시만 15분 이상.
  다만 크기가 유일한 파일은 읽지 않고, 앞 64KB가 다른 파일은 전체를 읽지 않는다.
- 보고서 단계의 대부분은 엑셀 상세(중복 파일 행 전체) 쓰기다. 행이 104만 개를 넘으면 엑셀에서 끊고 전체는 DB에 남긴다.
- 윈도우는 파일 열기 비용과 백신 실시간 검사 때문에 리눅스보다 목록·해시가 느릴 수 있다. GitHub Actions 윈도우 결과로 비교한다.
- 실제 업무 PC 결과는 경로 없이 `요약숫자.json`의 숫자(파일 수·단계별 시간)만 옮겨 적는다.
